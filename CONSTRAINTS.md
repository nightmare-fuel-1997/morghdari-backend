| # | Date | Constraint | Impact | Decision / Workaround |
|---|---|---|---|---|
| C-01 | 2026-08-24 | Default `python` on this machine is 3.11; Blueprint pins 3.12 (installed but not default) | venvs would silently build on 3.11 | Always create venvs with `py -V:3.12`; CI image is 3.12 anyway |
| C-02 | 2026-08-24 | Docker Desktop installed but daemon NOT auto-running after boot | CI/dev gates impossible until started | Start Docker Desktop manually before working (`docker info` to check); ~5 s to become ready on this machine |
| C-03 | 2026-08-24 | Repo forces LF via `.gitattributes`, but Windows tooling (and some editors) still emit CRLF locally | Spurious whole-file diffs / noisy `git status` on touched files | Keep `.gitattributes` as the single source of truth (`* text=auto eol=lf`); never fight it per-file. Docker builds are unaffected (context is copied as-is) |
| C-04 | 2026-08-24 | Docs pinned `timescale/timescaledb:2-pg16` — tag never existed on Docker Hub (Hub exposes `latest-pg16`, exact pins like `2.29.2-pg16`) | Dev/CI/prod compose could not pull | Doc-first fix: all three backend_docs artifacts re-pinned to `2.29.2-pg16` (docs commit db4ef95); local compose mirrors; upgrades are now deliberate pin bumps |
| C-05 | 2026-08-24 | EMQX 5.5 crash-loops (`missing_mechanism_field`) when an authentication BACKEND env override is set without its MECHANISM pair — the old docs-only-BACKEND form is invalid on 5.5 | Dev EMQX container restarts forever, dashboard unreachable | Env overrides must always carry BOTH keys: `EMQX_AUTHENTICATION__1__MECHANISM=password_based` + `...__BACKEND=built_in_database` (docker-compose.dev.yml); ref comment committed in M0-07 |
| C-06 | 2026-08-24 | Blueprint §8 HEALTHCHECK targets `/api/v1/health/` which first EXISTS in v0.6 | The backend container reports `unhealthy` by design throughout v0.1–v0.5 despite serving fine | Accepted placeholder, not a bug: do NOT weaken/remove the HEALTHCHECK to make it green (Dockerfile ref). Monitor via logs until v0.6 lands the endpoint |
| C-07 | 2026-08-24 | `gateway_saloon_zones` declares a composite PRIMARY KEY (gateway_slot_id, saloon_id); composite PKs need Django ≥ 5.2 while §2 pins Django `<5.1` | Literal DDL un-transcribable | Surrogate AutoField id + UniqueConstraint(gateway_slot, saloon) carries identical uniqueness semantics; revisit if Django is ever bumped to 5.2 (then migrate to CompositePrimaryKey) |
| C-08 | 2026-08-24 | `gateway_sensor_mapping.gateway_hardware_id REFERENCES gateway_hardware_registry(hardware_id)` — but hardware_id has NO unique constraint (install history implies repeated ids) and PostgreSQL refuses an FK without one; the doc clause is un-executable SQL as written | Either enforcing UNIQUE on hardware_id breaks reinstall history, or the FK cannot exist | Shipped as plain VARCHAR column (no DB-level relationship) + app-level integrity check later; OWNER DECISION pending: enforce UNIQUE vs drop FK in doc (doc-first fix after retrospective) |
| C-09 | 2026-08-24 | Doc extends auth_user via raw ALTER TABLE (`is_platform_staff`) — under test settings' --nomigrations table synthesis, migration-only columns don't exist | Tests would run against a user table missing the column | Custom AUTH_USER_MODEL `accounts.User(AbstractUser)` with the field on the model — works identically with and without migrations; doc references to `auth_user` resolve to `accounts_user` |
| C-10 | 2026-08-24 | `alert_acknowledgements` is tenant data but its DDL has NO org_id — violates the doc's own AU-RLS invariant ("every tenant-scoped table carries denormalized org_id") so it cannot receive tenant_isolation | App-role reads of ack rows are unfiltered cross-tenant | Excluded from policy list pending OWNER DECISION (Tracker §7.3); recommended doc-first fix: add org_id like its peer tables |
| C-11 | 2026-08-24 | TimescaleDB 2.29 refuses compression + RLS on the SAME hypertable in EITHER order ("operation not supported on hypertables that have columnstore enabled" / "columnstore cannot be used on table with row security") — database.md Compartment 3 Steps 1–2 conflict with Compartment 8's tenant_isolation mandate on saloon_telemetry | The two documented requirements are mutually exclusive on the pinned image | Security-first interim: RLS ON / columnstore OFF for saloon_telemetry; retention 180 d kept (needs no compression); doc annotated + Tracker §7.1 owner decision (options: keep / security-barrier view / future TSDB release) |
