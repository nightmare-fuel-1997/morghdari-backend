**Added — M6-06/M6-07 the living dashboard (WebSocket)**

- **M6-06** `SaloonTelemetryConsumer` (Channels): `WS /ws/saloons/{saloon_id}/telemetry?token=<JWT>` — auth BEFORE cap (bad token never consumes a slot): no/invalid token or wrong org → close **4003**; at the D21 `ws_max_connections_per_user` cap (Redis Set + 300 s zombie-guard TTL refreshed on every inbound message) → close **4000**; register→re-check race guarded; drain fans `telemetry.update` out after each per-org commit (groups `saloon_{org_id}_{saloon_id}`; `is_buffered` rides the event).
- **M6-07** reconnect gap-fill: `{"action": "gap_fill", "since": ...}` → ordered `telemetry.gap_fill` from the hypertable in the claim's tenant context; optional `slot_id` filter; `GAP_FILL_MAX_ROWS=200` ceiling; friendly bad-`since` envelope; no server session state.
- ASGI wiring: `config/asgi.py` ProtocolTypeRouter + `config/routing.py`.

**Added — M6-09 Flutter compat adapter (contract v1.6.0-draft, Tracker §4o)**

## 5. Deployment notes

- Serve via ASGI (`config/asgi.py`) behind Daphne/Uvicorn; Redis must be reachable for the WS cap + group layer.
- `DATA_UPLOAD_MAX_MEMORY_SIZE` raised to 12 MB for O6 photo uploads; `MEDIA_ROOT` must be a writable volume.
- New setting: `REST_FRAMEWORK.DEFAULT_THROTTLE_RATES['auth_strict'] = '3/min'`.
- Channels sync consumers run in an executor thread with their own DB connection — socket tests need `transaction=True` (encoded in the WS suite).
