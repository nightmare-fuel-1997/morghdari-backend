## 2. Changelog (finalized, condensed from main-repo CHANGELOG [v0.5])

**Added — M5 provisioning + zero-touch**

- **M5-01** Transition service (`apps/provisioning/services.py`): atomic status flip + `provisioning_audit_log` row + status-cache invalidation; every lifecycle action goes through it (no direct `provisioning_status` saves).
- **M5-02** Gateway-request flow: manager-submitted requests with config cap (`max_pending_gateway_requests`), platform review (admin/support by default via the new `User.staff_role` axis — migration 0002 — extensible via an optional `PlatformPermission` stub); approval creates slot + bcrypt credentials + EMQX allow-rule; plaintext password issued exactly once.
- **M5-03** Installer sync (`POST /api/v1/provisioning/sync/`): zones, sensor-slot mappings (hardware derived server-side, forged ids ignored), hardware `replacements` (validated before ANY write); per-slot Redis lock → `PENDING_APPROVAL`; second concurrent sync → 409 + Retry-After.
- **M5-04** Telemetry trust boundary in the subscriber pipeline: status-aware routing — `PENDING_APPROVAL` → `telemetry:pending_approval` FIFO; `REJECTED`/`SUSPENDED` → DLQ archive (`gateway_rejected` / `gateway_suspended`); no-record (legacy/demo) flows normally.
- **M5-05** FM lifecycle: approve (drains held FIFO into Postgres in order), reject (archives held telemetry to the DLQ), suspend (revokes ACLs), resume (re-syncs allow-rules); Blueprint §11 state matrices enforced → 409 on illegal transitions, zero partial writes.
- **M5-06** Gateway config (`GET /api/v1/gateways/{id}/config/`): R2 payload (org/farm ids, MQTT endpoint, credential hash + `rotation_pending`, NO sensor slot_ids, `rate_limit_note`); works pre/post approval; 403 on rejected/suspended; dual auth — device Basic-auth against its bcrypt credential OR farm manager/owner JWT.
- **M5-07** EMQX ACL wiring (`apps/mqtt_auth/services.py`): built-in-DB authorizer synced from `mqtt_acl_rules`; revocation empties rules ⇒ broker denies; FNV-soft (DB rules remain the truth). Gateway **authn user** created at approval with the one-time plaintext (EMQX 5.5 rejects pre-hashed `password_hash` — verified live); review approval pins the real publish topics `{org}/farms/{farm}/gateways/{slot}/{telemetry,status}` (the old `org/.../gateway/#` shape matched nothing under `no_match=deny`).
- **M5-08** Staged rotation: stage (pending bcrypt hash, old credential stays live), commit-on-ACK (promotes ONLY when the device presents the new password), 24 h stale-rotation beat sweep; commit pushes the new password to the EMQX authn user (404-heal self-converges a wiped broker); request-approval credentials now hashed with EMQX-native `$2b$` bcrypt (C7) instead of `bcrypt_sha256`.
- **Live broker verification** (`scripts/live_verify_emqx.py`) against real EMQX 5.5.1 — 10/10 checks green; **real-EMQX CI job** (`docker compose -f docker-compose.ci.yml run --rm live-verify`) so M5-07/M5-08 semantics are never only mocked.
- **Demo dashboard** completed (`apps/telemetry/demo_views.py`): identity, sensor health, rolling telemetry stats, per-slot breakdown, EMQX status, simulate + farm topology + seed commands.
- Subscriber boots resilient to broker downtime (2 s retry), subscribes to the status topic, mirrors LWT into pack-liveness keys.

**Deprecations / mechanism changes**

- PostgreSQL-backed EMQX authn (auth-query JOIN) **replaced** by built-in-DB authn + authz for the deployed/CI profile — see Tracker §4m (docs sweep of `emqx/emqx.conf`, MQTT Topic Map §3, Saas §9 is OPEN).
- Request-approval credential hashing moved from Django `bcrypt_sha256` wrappers to EMQX-native `$2b$` bcrypt (C7).

## 5. Live-verification results (staging sign-off)

- **Environment:** local Docker stack — timescale/timescaledb:2.29.2-pg16, redis:7-alpine, EMQX **5.5.1** (dev-profile broker: built-in-DB authn, deny-by-default authz, bootstrap API key), backend + subscriber from the v0.5 tree.
- **Commands:** `scripts/emqx_provision.py` (provision authn users + per-farm ACL rules) → `scripts/live_verify_emqx.py` (10 checks) → `docker compose -f docker-compose.ci.yml run --rm live-verify` (CI form).
- **Results — 10/10 green:** plaintext user creation is the broker contract (pre-hashed `password_hash` rejected — surfaced a real EMQX 5.5 behavior); wrong-password CONNECT rejected; allow-rule publish delivered; **revoke-to-empty drops delivery** (`no_match=deny`); rotation: new password connects, old rejected after commit; 404-heal self-converges a wiped broker.
- **Latency note:** broker ACL cache TTL (~1 min) bounds how fast revocation reaches an already-connected client — suspension is instant for new CONNECTs, up to ~1 min for live sessions (documented in TASKS M5-07).
- **Pass/fail metrics:** 10/10 pass, 0 fail; CI gate 284/284 pass (3 skipped by design).

## 6. Deployment notes (v0.5 delta)

- MQTT auth services speak to the EMQX 5.x management API (`EMQX_API_URL`/`EMQX_API_USER`/`EMQX_API_PASSWORD`, defaults `http://127.0.0.1:18083` demo-admin/dev_password); ACL enforcement is FNV-soft — broker outage logs, DB rules stay the source of truth.
- Provision the broker for the demo with `scripts/emqx_provision.py`; `no_match=deny` is set at broker bootstrap.
- New env contract for the subscriber: `SUBSCRIBER_CLIENT_ID` (required), `MQTT_HOST`/`MQTT_PORT`/`MQTT_USERNAME`/`MQTT_PASSWORD`, `REDIS_URL`.
- Config payload carries `rate_limit_note` — throttle MQTT CONNECT + publish per gateway at nginx (`limit_req`); broker-level quotas land with the v1.0 quota engine.
- Test-suite Redis URLs derive from the env URL (host `localhost` locally, `redis` service name in Docker); fresh CI volumes get `morghdari_app` table grants at session setup.
